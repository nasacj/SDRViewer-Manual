Install rtl_tcp on a Raspberry Pi

The least trouble of the four: power it and it runs, no computer left on, and with a power bank it goes to the balcony, the car or the airport fence.

This assumes the Pi already runs Raspberry Pi OS, is on Wi-Fi, and you can log in over SSH or with a screen. If not, write a card with the official Raspberry Pi Imager, which can set the Wi-Fi and turn on SSH as it writes.

  1. Install the tools and check the receiver 
    sudo apt update
sudo apt install rtl-sdr
rtl_test -t

    Found 1 device(s) and the model name mean it is working. For problems see the Linux page; the steps are the same.

    Using an RTL-SDR Blog V4 or V4L? Read a newer driver below first: the one the system ships may not recognise it.

  2. Make it a service that starts at boot

    Open an editor on a new service file:

    sudo nano /etc/systemd/system/rtl_tcp.service

    Paste this, then Control + O, Return to save and Control + X to leave:

    [Unit]
Description=rtl_tcp for SDRViewer
After=network-online.target
Wants=network-online.target
StartLimitIntervalSec=0

[Service]
ExecStart=/usr/bin/rtl_tcp -a 0.0.0.0 -p 1234
Restart=always
RestartSec=3
KillSignal=SIGINT
TimeoutStopSec=5
DynamicUser=yes
SupplementaryGroups=plugdev

[Install]
WantedBy=multi-user.target

    Enable it and start it now:

    sudo systemctl daemon-reload
sudo systemctl enable --now rtl_tcp

    Restart=always is what brings it back: if the receiver is unplugged or the program exits, it is tried again every three seconds, so plugging the receiver back in is enough.

  3. Check it is running 
    systemctl status rtl_tcp

    active (running) is what you want. journalctl -fu rtl_tcp shows its output.

  4. Find the Pi's address 
    hostname -I

    Or use its name: a Pi announces its hostname, so raspberrypi.local (or the name you gave it, plus .local) usually works in the app, with no numbers to remember.

The Pi is ready. Next: Connect in the app →

RTL-SDR Blog V4 / V4L: a newer driver

These two need a recent driver (librtlsdr): 2.0.2 or later for the V4, 2.0.3 or later for the V4L. With an older one, rtl_tcp still starts, the app still connects and the waterfall moves, but nothing is received — which looks exactly like an antenna or gain problem.

Check that this is the problem

rtl_test and rtl_tcp cannot share a receiver, so stop the service first:

sudo systemctl stop rtl_tcp
rtl_test -t

A receiver that is recognised prints RTL-SDR Blog V4 Detected or RTL-SDR Blog V4 Lite Detected. Only Found Rafael Micro R820T tuner, with no such line after it, means the driver is too old. Control + C to stop it.

Then see which system and driver you have, which decides the method:

grep VERSION_CODENAME /etc/os-release
dpkg -l librtlsdr0 | tail -1
SystemDriver it shipsWhat to do
trixie (Raspberry Pi OS from late 2025)2.0.2: the V4 works, the V4L does notMethod 1: install Debian's 2.0.3 packages
bookworm or older0.6.0: neither worksMethod 2: build from source, or write a new card

Method 1: trixie — install Debian's 2.0.3 packages

A newer Debian already has 2.0.3, and its two packages install on trixie as they are, with no change to the package sources:

sudo systemctl stop rtl_tcp
cd /tmp
arch=$(dpkg --print-architecture)
wget http://deb.debian.org/debian/pool/main/r/rtl-sdr/librtlsdr0_2.0.3-1_${arch}.deb \
     http://deb.debian.org/debian/pool/main/r/rtl-sdr/rtl-sdr_2.0.3-1_${arch}.deb
sudo apt install ./librtlsdr0_2.0.3-1_${arch}.deb ./rtl-sdr_2.0.3-1_${arch}.deb
rtl_test -t

Once it prints RTL-SDR Blog V4 Lite Detected, Control + C and start the service again:

sudo systemctl start rtl_tcp
  • $(dpkg --print-architecture) fills in arm64 (64-bit system) or armhf (32-bit).
  • A 404 when downloading means Debian has moved to a newer version number: open this folder, find the two files starting librtlsdr0_ and rtl-sdr_, version 2.0.3 or later, for your architecture, and put that version in the commands.
  • Install just these two packages. Do not add Debian's testing release to your sources: the system would then offer to upgrade everything to it.
  • sudo apt upgrade will not put the old version back. When trixie itself ships 2.0.3 or later, it replaces these in the ordinary way.

Method 2: bookworm or older — build from source

Debian's 2.0.3 packages need newer system libraries than bookworm has and will not install there. Build RTL-SDR Blog's own version instead (a few minutes on a Pi 4 or 5):

sudo systemctl stop rtl_tcp
sudo apt purge ^librtlsdr rtl-sdr
sudo apt install git cmake build-essential pkg-config libusb-1.0-0-dev
git clone https://github.com/rtlsdrblog/rtl-sdr-blog
cd rtl-sdr-blog
mkdir build && cd build
cmake .. -DINSTALL_UDEV_RULES=ON
make
sudo make install
sudo ldconfig
echo 'blacklist dvb_usb_rtl28xxu' | sudo tee /etc/modprobe.d/blacklist-dvb_usb_rtl28xxu.conf

This installs into /usr/local/bin, not /usr/bin, so the service file must change: ExecStart=/usr/bin/rtl_tcp becomes ExecStart=/usr/local/bin/rtl_tcp.

sudo sed -i 's|/usr/bin/rtl_tcp|/usr/local/bin/rtl_tcp|' /etc/systemd/system/rtl_tcp.service
sudo systemctl daemon-reload

Then unplug the receiver and plug it back in, so the new permission rule applies to it, check it and start the service:

rtl_test -t
sudo systemctl start rtl_tcp

The other way is to write a fresh card with Raspberry Pi Imager — current images are trixie — and use method 1. For a Pi that only runs rtl_tcp, that is often less work.

Still not working

  • usb_open error -3 in journalctl -u rtl_tcp: the permission rule has not reached this receiver yet. Unplug it and plug it back in, or restart the Pi.
  • rtl_test says the device is busy: the service is still running. sudo systemctl stop rtl_tcp first.

Taking it outdoors

  • Power: a Pi 4 or 5 with one receiver wants a power bank that gives 5 V at 3 A. Short of power, the Pi slows down and the audio stutters.
  • Network: turn on the iPhone's Personal Hotspot and have the Pi join it (set that up at home first). The phone then has the internet and the Pi at once.
  • Two receivers: a Pi can hold two, each with its own rtl_tcp on its own port (1234 and 1236, say). Add one entry for each to the app's receiver list, and you can listen to air traffic while watching ADS-B.
