Aviation 航空数据链

飞机和地面之间除了说话，还一直在互发文字：要通播、要放行许可、报告推出和起飞时刻、收天气。这些报文走的是 ACARS 和 VDL2 数据链。这一页把它们收下来，按飞机和航班排好，并把常见的报文解读成一张看得懂的表。

关于截图。本页的报文是为手册编写的演示数据：飞机 .NDEMO1、航班 XD0101 都不存在，内容仿照真实报文的格式，背景设在洛杉矶。你收到的真实报文样子相同。收到的内容请只用于自己学习，并遵守当地的法规。

开始接收

  1. 选对地区点右上角的 … → Settings，在 Region 里选你所在的地区。各地用的频率不同：中国是 131.450 MHz，北美是 131.550 MHz，欧洲又是另一组。选错了就是在听一段空的频率。
  2. 点播放键接收机会同时监听这个地区的几个频率。Listen around 可以换一组频率，或者改收 VDL2（136.975 MHz 一带，更新的一种数据链）。
  3. 等一会儿数据链是一阵一阵的短促发射，不像广播一直有信号。在机场附近几十秒就有一条，离机场远的地方可能要等几分钟。顶上的 msgs 是已经收到的报文数。

天线用收航空波段的那一种（和 ATC 页一样），并且要做过频率校准：这里的信道很窄，偏一点就完全收不到。

三层：飞机 → 航班 → 报文

  • 飞机：按注册号（相当于飞机的车牌）列出，下面的小字是它执飞的航班号，右边是报文数量（8/13 表示 13 条里有 8 条是有内容的）和最后一次收到的时间。
  • 航班：点进一架飞机，报文按航班分组、按时间排列（就是本页第一张图）。
  • 报文：点任意一条，看完整解读。WHAT IT SAYS 是解读出来的内容，AS RECEIVED 是收到的原文，一个字都不改。
一条报文上的标记

TX 是飞机发出的，RX 是地面发给飞机的。LBL 后面是报文的类型代码（B9、A9、B3…）。右边是收到它的频率。inferred 表示这条报文本身没写航班号，是根据同一架飞机前后的报文归到这个航班的。标题那一行是报文的类型，下面是解读出来的各项内容。

右上角的中文按钮把解读切换成中文：字段名变成中文，机场代码后面会带上机场名。

跟着一架飞机看一次离场

把一架飞机起飞前的报文连起来看，就是一次完整的离场准备。演示里的 XD0101 从洛杉矶飞往旧金山：

顺序方向报文在做什么
1飞机 → 地面Request ATIS Report机组索取洛杉矶的离场通播。
2地面 → 飞机Deliver ATIS Information通播发到驾驶舱：编号 K，离场跑道 25R，气压 1015。
3飞机 → 地面Departure Clearance Request申请放行：我在 41 号登机口，去旧金山，已收到通播 K。
4地面 → 飞机Flight System Message“申请已收到，正在处理，请等待。”
5地面 → 飞机Departure Clearance Message放行许可：跑道 25R，离场程序 ORCKA5，应答机 4301，初始高度 5000 英尺，下一个频率 121.750。
6飞机 → 地面Departure Clearance Read Back机组把许可原样复诵回去，表示确认。
7飞机 → 地面Departure（OUT）18:26 推出登机口，机上燃油 9800。
8飞机 → 地面Departure（OFF）18:34 离地。

这些内容在语音频率里是听不到的。大机场的放行许可现在多数走数据链，而不是在放行频率上念。

放行许可里写了什么

字段含义
CLRD TO许可飞往的目的地机场。
RUNWAY起飞跑道。
SID离场程序的名字：起飞后沿哪条固定路线离开机场。
SQUAWK应答机编码。在 ADS-B 页的标牌第一行能看到同一个数字。
ADT批准的起飞时刻。
INITIAL ALT起飞后先爬到的高度。
NEXT FREQ下一个要联系的频率（这里是地面）。
APP FREQ起飞后联系的进近 / 离场频率。
ATIS机组已经收到的通播编号。

把离场程序画到地图上

放行许可里的 ORCKA5 只是一个名字。如果你导入了航图数据文件，报文下面会出现一个按钮 Show departure ORCKA5 · 25R on the map，点一下：

这架飞机接下来要飞的路线就在眼前：从 25R 跑道起飞，经 DOCKR、KLIPR、KEGGS、COOPP，到 ORCKA。地图下面列出了每一个航路点。

三个页面在这里连了起来：

  • Aviation 告诉你这架飞机被许可飞哪条程序、用哪个应答机编码。
  • ADS-B 里打开同一条离场程序，几分钟后就能看到它起飞、沿着这条线飞出去，标牌上是同一个编码。
  • ATC 里切到许可中写的下一个频率，听它和地面、塔台的通话。

只有当许可里的程序名、机场和跑道在你的数据文件里能唯一对上时，按钮才会出现。对不上时页面会直接说明原因，不会画一条“差不多”的路线。

还能收到哪些报文

类型内容
数字通播（D-ATIS）机场的使用跑道、天气、气压。和语音通播内容相同，但是文字。
放行许可（DCL）申请、受理、许可、复诵，就是上面那一串。
推出、起飞、落地、到位航空公司用来统计准点的四个时刻，通常带起降机场和燃油量。
天气发给机组的 METAR 实况和 TAF 预报，切到中文显示时会解读成风、能见度、云、温度。
位置报告飞机报告自己的坐标、高度、预计到达时间。
机务报告发动机参数、故障代码。能认出是哪个系统，更细的含义属于厂家的手册。
链路测试和确认Link test、Ack：飞机和地面互相确认链路通畅，没有内容。数量最多。
频率切换地面通知飞机改用另一个数据链频率。页面会提示有哪些频率是你现在没在听的。
未解读各家航空公司自定义的格式很多。认不出的报文标为未解码，只显示原文。

设置里的 Content only 默认打开：飞机列表只按有内容的报文来排，只发过链路测试和确认的飞机不占位置。

常见情况

现象原因和办法
一直是 0 条先看 Region 选得对不对；再确认做过频率校准；然后多等几分钟。离机场远、天线在室内时，可能确实收不到。
syncs 在涨，msgs 不涨收到了信号的开头，但内容校验没通过，说明信号偏弱。改善天线位置。少量这样的情况是正常的。
只有 Link test 和 Ack正常，这两种本来就最多。有内容的报文集中在飞机起飞前和落地后，在机场附近更容易收到。
飞机下面没有航班号只有飞机发出的报文带航班号。如果只收到了地面发给它的，就只能按注册号显示。
提示有别的频率没在听接收机一次只能覆盖约 1 MHz。有些机场的流量在另一组频率上，在 Listen around 里换过去试试。
放行许可下面没有地图按钮没有导入航图数据文件，或者文件里没有这条程序。按钮位置会有一行说明。
很多报文是未解码正常。航空公司自定义的格式没有公开的说明，App 不会去猜。
